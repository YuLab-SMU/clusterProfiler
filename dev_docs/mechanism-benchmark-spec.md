# 机制归属第二期：两个基准分开做

状态：设计稿 v2（审核后重写）。日期 2026-11-05。
前序：`mechanism-attribution-postmortem.md`（第一期为什么收口）、
`pathway-mechanism-design.md`（第一期方法）、本文件 v1（已废弃，错误见 §9）。

> **v1 的致命错误**：把"条件实验里认出驱动者"和"敲低签名里认出被敲的基因"
> 当成同一个任务。两者实测差 0.19 AUC（0.749 vs 0.563），混在一起会把
> 388 份敲低数据上得到的 ~0.56 写成"旧实现在大样本上只有 0.56"——换了问题。
> 本期把两个基准显式分开。

---

## 0. 一句话

**基准 A（条件实验 → 驱动者）扩容到 20，用小样本指标；基准 B（敲低签名 → 被敲基因）
用 KnockTF 过滤后的 299 份实验跑满，用 decoupler 的连续指标。两者分开报数，不合并。**

第一期确立的三条结论继续有效，本期只扩容、不改方法：
旧实现不因换统计量提升（五次尝试同一条权衡线）；预检门是唯一原样站住的层
（失败 7/7 挡住、成功 0/4 误伤）；13% 必需基因假阳性是 evidence-substrate mismatch。

## 1. 两个基准（为什么不合并）

|  | **基准 A：驱动者恢复** | **基准 B：签名识别** |
|---|---|---|
| 查询 | 条件实验的整条 DE 向量 | 一份 TF 敲低/敲除的 log2FC 矩阵列传 |
| 真值 | 实验设计的干预对象 | 被敲的 TF |
| 回答 | "这个处理由谁驱动" | "这份签名来自谁" |
| 现成规模 | **11** | **907**（可扩到 456 个 TF） |
| 第一期实测 | AUC **0.749**，A 4/11、A 或 B 6/11 | AUC **0.563**（20 份跨数据集留一，**经验签名矩阵**作先验）；P1 换成策展网络（CollecTRI、去自环）后 **0.677**，随机基线 0.54 |
| 本期目标 | 扩到 **20** | 跑满 **907** |

**它们是两个问题，答案也不一样。** A 是产品要回答的（用户有处理、想知道驱动力），
B 是发现模式（用户没有先验、只有一份签名）。第一期的所有产品判断建立在 A 上，
所有"接近随机"的判断建立在 B 上——混着报就会得出"我们的方法在大样本上崩了"这种
假结论。

## 2. 数据

### 2.1 基准 B：KnockTF 2.0，直接可用

`decoupler.ds.knocktf()` 从 Zenodo 7035528 下载两个文件（实测元数据）：

| 项 | 数 |
|---|---|

| 元数据 `knockTF_meta.csv` | **907 行**（实验）× 14 列 |

| `type_p` | 全部 −1（都是敲低） |

**两道过滤都要算，v2 的第一版漏了它们**（v2 写"预期 700–900"，实测差 3 倍）：

|---|---|---|

| ∩ 参考网络收录 | 512 份 / **180 TF** | 691 份 / **303 TF** |
| 再 ∩ `logFC ≤ −1` | 217 份 | **299 份 / 171 TF** |
| 其中 ≥2 个生物样本的 TF | 35 | **49** |

**主实验用 CollecTRI（299 份 / 171 TF），DoRothEA 作为网络对照**（decoupler 的教程本身
就是多网络对比，这不是额外工作）。

**P1 实测修正（2026-11-05）**：上面是"网络 ∩ 阈值"的算法估计；真正进入 benchmark 的是
**279 份 / 155 个 TF**——`bm.benchmark(sfilt=True)` 去掉 109 份 source 不在网络里的实验，
再用 `prune(tmin=5)` 去掉靶基因不足 5 个的 TF。两个数都在 `results/p1/P1_REPORT.md` 里。

### 2.1b `thr_fc` 的取舍（必须写死，v2 没做这个决策）

`logFC` 是**敲低效率**：907 份的中位数只有 −0.82（四分位 −1.53 / −0.27），
一半以上敲低不彻底。阈值直接决定多少驱动者能进入评估：

| 阈值 | 实验数 | 影响 |
|---|---|---|
| `None` | 691 | 含弱敲低，噪声大 |
| **−1（decoupler 默认，主用）** | **299** | 干净；但 ARNT/ESR1/NR3C1 归零（见 §4.2） |
| −0.5 | 583 | 多一倍；需做敏感性分析 |
| −1.5 | 234 | 更严 |

**决定**：主结果用 **−1**；**−0.5 作为敏感性分析**一并报（同一套指标，两行）。
理由：−1 是 decoupler 的默认、也是"敲低到 50% 以下"的常用线；
把 −0.5 的结果并列而不选它，是为了不让"阈值选择"变成事后叙事。

**关键事实（v1 写错的地方）**：KnockTF 给的是**已算好的 log2FC**，不是原始 counts。
所以基准 B **直接用它给的 log2FC**（decoupler 的 benchmark 本来就是吃 log2FC 的），
不需要重算 DE——这不是妥协，是它的设计。

纳入判据（跑之前写死）：

| 条件 | 阈值 | 理由 |
|---|---|---|
| TF 在参考网络里 | DoRothEA/CollecTRI 收录 | 没有 regulon 就没法给该 TF 打分 |
| 敲低强度 | 元数据 `logFC` ≤ −1（默认 `thr_fc=-1`） | decoupler 内置口径，保留默认 |
| 基因覆盖 | 与 **CollecTRI 靶基因并集**的交集 ≥ 5,000 | 太少则打分不稳（基准 B 不用 `all11` 参考矩阵） |
| 细胞系唯一性 | **不去重**（decoupler 也不去重）；若去重则 299 → 277，作为敏感性一行报 | 同一细胞系的不同研究是独立实验，不算重复计权 |

预期：**299 份实验 / 171 个 TF**（CollecTRI + `logFC ≤ −1`），
DoRothEA 对照 217 份（见上表）。

KnockTF **没有条件实验**（全是敲低/敲除）。所以基准 A 的数据来源还是 GEO，
和第一期 11 份的取得方式完全一样。

本期只做"11 → 20"：再找 9 份满足下列条件的条件实验（判据沿用第一期，写死）：

| 条件 | 阈值 | 来源 |
|---|---|---|

| 通路集中度 | enrichGO(BP, 上调基因, p<0.05) ≥ 10 条显著 | GSE311462（550 上调 / 0 条）教训 |

唯一失败是 STAT1/IFN-γ（1405 上调、484 条 GO，全部 C），留作下一轮首要排查。

**扰动臂**：驱动者的扰动数据优先用 GPSAdb（第一期已通），KnockTF 作为补充来源

## 3. 指标

### 3.1 基准 A（n=20）：hit/miss + AUC

小样本撑不起 PR 曲线（第一期已证）。只报：

- **命中率**：A 级命中 / A 或 B 命中，两个数分开；
- **AUC**：真值在候选里的排名百分位均值；
- **预检门触发率**：挡住多少、误伤多少。

### 3.2 基准 B（n≈300）：decoupler 三组指标

| 指标 | 定义 | 测什么失败 |
|---|---|---|
| `auc` | AUROC 与 AUPRC 的调和均值（AUPRC 做类不平衡校准，随机 = 0.5） | 排序能力 |
| `fscore` | 按方向过滤后 precision/recall 的调和均值 | 阈值行为 |
| `qrank` | 分位秩 + Wilcoxon 检验的调和均值 | 区分度（第一期"埋在第 18/200"问题的正式度量） |

**必做的两个对照**（decoupler 内置，第一期我们没做）：

1. **随机网络基线**（`shuffle_net`）：协议自检——若真网络与随机网络得分接近，
   说明这个方法在这一批数据上没有信息；
2. **去方向对照**（unweighted）：分离"网络本身有信息"与"符号方向有信息"。

**参赛者**：decoupler 的 `ulm`、`mlm`、`ora`、`gsea`、`viper`、`consensus` +
**我们第一期的 es（均值位移）**。

⚠ **必须排除自环**（P1 发现，spec 第一版漏了）：CollecTRI 里 1,185 个 TF 有 461 个带
`source == target` 自环；进入评估的 155 个 TF 里 **96 个（62%）带自环**。敲低实验里 TF
自己的 log2FC 是最强信号之一，自环等于**把答案编码进题目**。实测去掉自环后
ulm 的 auc 从 0.728 掉到 **0.677**（−5.1 点）。
协议固定为：`net = net[net.source != net.target]`。

⚠ **v1 在这里写错了**（"把 es 塞进 `waggr`"）：es 的形态是 `score(扰动, 通路)`，
decoupler 是 `score(TF, 样本)`，角色对不上。正确做法是**把 es 当作一个 decoupler 方法实现**：
给定网络（regulon = TF 的靶基因集）和一份 profile（某 TF 的敲低 log2FC 向量），
`es(TF) = mean(profile over TF 的靶基因) / (sd/sqrt(n))`。

⚠ **它与 `ulm` 相关但不同**（v2 的第一版写成"数学同构"，错）：`ulm` 是**双样本**
（靶基因 vs 非靶基因，分母含背景方差），我们的 es 是**单样本**（对 0 检验）。
背景方差大时两者会明显分歧——这正是要测的东西：

- 若一致 → 说明第一期"均值位移"的结论可以迁移到 decoupler 的坐标系；
- 若不一致 → **先查是不是背景方差造成的**（把 es 换成双样本口径再跑一次），
  再判断是不是方法族本身的差异。

不许把"不一致"直接读成"我们的方法更好"或"更差"。

### 3.3 不做的事

- **不做 PR 曲线上的操作点**（基准 A 的 n 不够，基准 B 的类别极不平衡）。
  §2.1b 把 `thr_fc = −1 / −0.5` 两行并列，是**敏感性分析**——报"结论对阈值有多敏感"，
  不是挑一个当操作点。两者不是一回事。
- **不移植 decoupler 的方法实现到 R**。

## 4. 复现率（Q3）

### 4.1 定义（必须独立于 `pathway_evidence`）

对某个（驱动者 d，通路 P）：

```
k         = d 在过滤后仍有数据的扰动数据集数；**k ≥ 2 才计算，否则返回 NA**
shift_i   = P 的成员在 d 的第 i 份扰动数据集上的平均 log2FC
reproduction(d, P) = sign(shift_i) 与多数派符号一致的那几份 / k
majority_sign      = sign(sum(shift_i))       # 单独一列报出
```

**为什么不是"与 P 的方向一致"**（v3 的第一版写错，符号级错误）：
对激活型驱动者，敲低应当让 P **下调**——与 P 的方向**相反**。按"一致"算，
HIF1A 敲低会得到复现率 0，而且**越是真的驱动者越接近 0**。

改成一致性（concordance）后，它只问"这几份数据是不是都往同一个方向推"，
不需要预先知道 d 是激活型还是抑制型；至于那个方向是否符合生物学预期，
是 `majority_sign` 与条件实验方向对比时**另外**判断的事。

**方向判定不经过 `pathway_evidence`**——直接用 log2FC 矩阵算成员均值，
否则是拿同一统计量校准自己的措辞（第一期 §7.10 记过一次自引用）。

**单份数据集的处理**：k = 1 时一致性恒为 1，没有信息。这种情形
`reproduction` 返回 `NA` 而不是 1——否则"只有一份数据"会被算成"完美复现"。

### 4.2 KnockTF 能覆盖多少（实测）

12 个第一期驱动者里（**过滤后才算数**：网络收录 + `logFC ≤ −1`）：

| 驱动者 | KnockTF 实验 | 过滤后 | 生物样本（过滤后） | 可算复现率 |
|---|---|---|---|---|
| HIF1A | 8 | 7 | 5 | ✓ |
| STAT3 | 12 | 10 | 9 | ✓ |
| TP53 | 12 | 8 | 8 | ✓ |
| AR | 11 | 4 | 4 | ✓ |
| NFE2L2 | 3 | 1 | 1 | ✗ |
| AHR | 1 | 1 | 1 | ✗ |
| **ARNT** | 4 | **0** | 0 | ✗ |
| **ESR1** | 6 | **0** | 0 | ✗ |
| **NR3C1** | 1 | **0** | 0 | ✗ |
| EPAS1 / VHL / VDR | 不在库 | — | — | ✗ |

**可算复现率的只有 4 个：HIF1A、STAT3、TP53、AR。**（v2 的第一版写 7 个，是按未过滤
数据算的。）

三个驱动者**过滤后归零**，原因不是"库里没有"，而是"库里有但敲低不到位"：
ARNT 4 份、ESR1 6 份、NR3C1 1 份，全部 `logFC > −1`。这比"没有数据"更值得写下来——
它说明这条数据库的覆盖问题不是数量，是**敲低质量**。

**NR3C1 是第一期两个停在 B 的案例之一**（airway 与 GSE286890 的 GR）。现在不只是
"只有 1 份"，而是"过滤后 0 份"。所以 Q3 对 GR 的结论要写死为：
**不是算不出来，是库里没有能用的数据**——回 GPSAdb 也只有 1 个细胞系（第一期已查）。
B 级措辞的复现率校准，对 GR 这个案例做不到。

### 4.3 分级（写死）

| 复现率 | B 级措辞 |
|---|---|
| ≥ 0.9，且 **k ≥ 3 份数据集、来自 ≥2 个不同 Biosample** | 追加 "and reproduces across N independent datasets"（N = Biosample 数） |
| 0.5–0.9 | 保留现措辞 "likely, but under-evidenced" |
| < 0.5 | 改中性 "only one dataset; no independent reproduction available" |
| 无法计算 | 同 < 0.5（**不能默认算通过**） |

做成 `pathway_evidence(reproduction_rate = FALSE)` 的可选参数，默认关闭
（依赖 KnockTF 接入，不能成为硬依赖）。

**覆盖率要写在函数文档里**：12 个第一期驱动者里只有 4 个能算复现率。
一个"12 个里 8 个返回 NA"的参数，如果不说明，用户会以为它坏了。

### 5.1 预登记的决策规则（v1 缺的）

| 观测 | 决策 |
|---|---|
| 基准 B 的 `auc` ≥ 0.7 且显著优于随机网络 | 发现模式可进产品（作为候选排序），并重开第一期否掉的归属路线 |
| 基准 B 的 `auc` 在 0.5–0.6 | 维持第一期结论：发现模式不作为产品能力，只作候选生成 |
| 基准 B 的 `auc` < 0.5 | 说明方向反了（敲低签名与程序反相关），需查符号约定 |

**P2 实测（2026-11-05）触发第一行**：DoRothEA × mlm = **0.712**，
Δ(真实−随机) 的 bootstrap 95% 区间 [0.173, 0.277]（CollecTRI 为 [0.071, 0.175]），
两者都显著。裁决：**发现模式可作候选排序，不可作判定**——precision 只有 0.028，
规则里"作为候选排序"这个限定词是这条裁决的全部内容。

附带两条实测：
- **我们的 es（waggr）是真实方法里最弱的之一**（0.583/0.631 vs ulm 的 0.677/0.696）；
  要用发现模式就不该用单样本 es，该用双样本线性模型；
- **网络大小不等于质量**：DoRothEA（367 TF）全面胜 CollecTRI（1,185 TF），
  与第一期"加库稀释判别力"一致。

**"显著优于"的定义（审核补充，必须写死）**：对 299 份实验做 **1,000 次配对 bootstrap**
（每次重抽实验），计算 `auc(真实网络) − auc(随机网络)` 的 95% 百分位区间；
**区间下界 > 0 才算显著**。不用单次全量跑出的点差异——那是第一期"用 9 个点定操作点"的同一种错。

**这条规则写在跑之前，跑完不改。**

**若装不上**（依赖冲突 / 无 PyPI 访问），fallback 是按 decoupler 的公式在 R 里实现
三个指标——公式已从源码确认（`auroc`：梯形积分；`auprc`：`pi0=0.5` 的 Siblini 校准；
`qrank`：分位秩 + Wilcoxon 调和）。**这条 fallback 是计划内的，不是失败预案**：
三个指标一共约 60 行 R，重写一遍比卡在环境上便宜。

## 6. 明确不做的

- **不把 CollecTRI 接进 `mechanism_sets()`**（产品侧）。理由不是"网络没用"——
  P2 证明在**发现模式**（基准 B）下策展网络就是瓶颈（0.712 vs 随机 0.47）。
  理由是产品走的是**归属**（基准 A），归属的瓶颈在扰动数据覆盖与细胞系，不在靶网络。
  若日后真做发现模式，用 **DoRothEA**（P2 里全面胜出），不是 CollecTRI。
- **不做鼠/拟南芥/玉米**。KnockTF 有 344+37+1 份，但第一期所有判据在人上校准。
- **不做 propose→verify 的 LLM 侧改造**（GeneAgent 模式）。那是 `interpret()` 层的事。
- **不重算 KnockTF 的 DE**（v1 写错）：它给 log2FC，基准 B 直接用。

## 7. 风险

| 风险 | 概率 | 对策 |
|---|---|---|
| decoupler 未安装（R/Python 都没有；`anndata` 已有） | **确定** | P1 第一步装 Python 包并固定版本；记录到环境说明 |
| 参考网络与 KnockTF 的 TF 名不一致（别名/家族） | 高 | 先做 TF 名交集报告，再决定用 DoRothEA 还是 CollecTRI；不一致清单进附录 |
| KnockTF 的 log2FC 与我们的 DE 口径不同（不同工具/阈值） | 高 | 基准 B 内只用 KnockTF 的矩阵，不混入我们的 DE；两套口径不交叉 |
| 基准 A 挖不满 9 份 | 中 | 停在 11，如实写（第一期 §7.2） |
| 过滤后只有 49 个 TF 有 ≥2 个生物样本 | 已知 | 复现率只能覆盖这 49 个；我们的驱动者里只有 4 个，如实写 |
| 我们的 es 与 ulm 口径相近（单样本 vs 双样本 t），结果可能接近 | 中 | 若一致，报告为"口径验证通过"，不是"新发现"；不一致时先查背景方差 |

## 8. 成功标准

> **口径提醒（审核补充）**：基准 B 验证的是**方法族**（线性模型 vs 扰动检验），
> 不是 `pathway_evidence()` 的代码路径。B 的结论可以直接说明"这类统计量在这类数据上
> 有多少信息"，**不能**直接当作"我们的函数好不好用"的证据——后者只在基准 A 上测。

- **基准 B**：299 份（CollecTRI，`logFC ≤ −1`）上给出 `auc`/`fscore`/`qrank` × 6 方法
  + 随机网络基线的一整张表，且我们的 es 在表里有一行；−0.5 与 DoRothEA 作为两行敏感性对照；
- **基准 A**：**17 份（独立数据集口径 14 份）** 的 hit/miss 与 AUC；目标 20 未达，缺口见 P3 报告；
- **复现率**：**4 个**可算的驱动者各有数，无法计算的如实标注（含 GR：过滤后 0 份）；
- 三个数都能被第三方的 decoupler 环境重跑（脚本 + 版本固定）。
