# 机制提出评估框架：实现规范

状态：待实现。日期 2026-10-29。
构想与论证见 `dev_docs/mechanism-evaluation-proposal.md`。

---

## 1. 目标与范围

把当前"四个例子 + 一个 54 数据集 benchmark"的验证，扩成**可重复、分层、含非循环负对照**的评估框架，并修掉审查中发现的覆盖不可见问题。

三块工作，按性价比排序：

| # | 工作 | 回答什么 | 需要模型 | 需要网络 |
|---|---|---|---|---|
| **E1** | 叙述错误注入套件 | precision 里**可离线的那一部分**：叙述出现未获准/越界符号时能否检出 | **否** | 否 |
| **E2** | 分层扩规模 benchmark | recall：找到率与名次，按真值可得性分层 | 否 | 是 |
| **E3** | 覆盖可见性 | 让"强"与"弱"看起来不一样 | 否 | 否 |

## 2. 决策

| # | 决策 | 理由 |
|---|---|---|
| **D1** | E1 注入的对象是**叙述文本**，不是 prompt | 注入 prompt 只能测"闸门挡没挡住"，而闸门逻辑已有单测。注入叙述测的是**安全检查本身灵不灵**，且完全离线、每一处错误都有确定答案 |
| **D2** | E1 的指标是**按错误类型的检出率 + 干净叙述上的误报率**，不合并成单分 | 与《单细胞…评估框架》§12-7 一致；合并会掩盖"某一类错误完全检不出" |
| **D3** | E2 **按真值可得性分层报告**，不报总体单值 | 「真值在 C3:TFT 里」是确定性分层，不需要人工标注；不分层会把两种完全不同的失败混成一个数 |
| **D4** | E2 增加**同 size 匹配随机集合**作为经验零分布 | 名次本身没有解释力；"比同规模随机集合好多少"才有 |
| **D5** | E3 **不改任何 verdict 判定**，只让覆盖可见 | 改判定会推翻已有结论，而那些结论本身没有错——它们只是缺一个"靠什么撑起来"的说明 |
| **D6** | 中性负例（组织无关真实基因集）进 E2 的负对照层 | 随机基因集是弱负例：显然无意义、工具不给结论是廉价的。真实集合才检验"会不会给出貌似合理的错误答案" |
| **D7** | E1 **只测现有检查器的能力边界**，不新增检测器；需要新检测器的错误类型另立方案 | 审查中实测出 `unsupported_claims()` 是**符号词表检查**，只覆盖 5 类错误里的 1–2 类。把它包装成"能测五类"会得出"五类里三类检出率 0%"这种真而无用的结论；先量清边界，再决定补什么 |
| **D8** | 顺手修掉 E1 暴露的**词表漏洞**：未获准、但符号出现在输入基因列表里的调控者，逃过检查 | 这不是设计取舍，是漏洞。词表 `vocab` 含输入基因，所以"ESR1 驱动了这个程序"这句话，只要 ESR1 在差异基因表里就完全放行。而**调控者常常正是差异基因**——MCF-7 里 ESR1 自身 lfc −1.94、padj 2e-4。漏洞恰好落在最需要它的地方 |

### 2.1 D8 已实现，且实际是两个缺陷

写进 D8 时只发现了一个，动手改的时候发现了第二个。两个都在同一条检查链上：

1. **输入基因豁免**：`vocab` 含输入基因，所以被裁决判过、且判为 `absent` 的调控者，只要
   符号同时在差异基因表里，就被当作"已解释"。修法：被判过而未获准的符号**不再享有豁免**
   （`graded_out`）。从未被判过的普通基因不受影响，所以不会把输入列表的每一次提及都报出来。
2. **族名豁免用错了集合**：`is_family_of_admitted()` 按注释应当只认**获准标签**，实际拿的是
   整个 `vocab`。于是 `MYB`（已判 `absent`）因为输入基因里有 `MYBL1` 而以"族名"被放过——
   而 `MYBL1` 自己也是个未获准的调控者。修法：族名判断改为只看 `admitted_labels`。

第 2 个必须先修，否则第 1 个修了也白修：MCF-7 的那 4 个边界符号（`MYB`、`MYBL1`、`PGR`、
`STAT4`）修了第 1 个之后仍然全部放行。

**真实数据验证**（MCF-7，ESR1 KO，66 输入基因 / 871 条 verdict）：

| 符号 | 性质 | 修前 | 修后 |
|---|---|---|---|
| `MYB` `MYBL1` `PGR` `STAT4` | 未获准 + 在输入基因 | 0 | **1** |
| `ESR1` `SPDEF` | 获准 | 0 | 0 |
| `GAPDH` | 未获准、非输入基因 | 1 | 1 |
| 只点获准实体的叙述 | — | 0 | 0 |

这个 bundle 里"未获准且同时是输入基因"的符号只有 **4 个**，所以修复不会造成误报洪水。

## 3. E1：叙述错误注入

### 3.1 为什么注入叙述

`interpret()` 的输出受 `adjudication` 约束。这条约束有两道：

1. **闸门**：未获准的实体进不了 prompt（`evidence_admitted()` 与 `consensus_findings()` 的白名单）——已有单测覆盖；
2. **安全检查**：模型仍可能写出越界句子，由 `unsupported_claims()` 逐主张核验。

第 2 道**在审查中已经量过了，结论是它的能力比初稿假设的窄得多**。

`unsupported_claims()` 的实现（`R/interpret_evidence.R:207`）只做一件事：把叙述里
形如基因符号的大写词抓出来，减去"已知词表"（获准实体名 + 背景基因 + 输入基因 + 停用词），
剩下的就是未解释的词。

实测（构造一个含 `HIF1A` 获准、`ESR1` 不获准的小 bundle）：

| 注入 | 结果 |
|---|---|
| `HIF1A drives it via TP53.` | 报 `TP53` —— 因为 `TP53` 不在词表，不是因为它未获准 |
| `HIF1A drives GAPDH.` | 报 `GAPDH` |
| `MYC is a proven mechanism.`（`MYC` 是 `single_source`） | **不报** |
| `ESR1 was not detected, so it is absent.` | 报 `ESR1`，但仍是符号不在词表；换成在词表里的实体就不报 |
| `HIF1A is repressed under this condition.`（与 `direction=up` 相反） | **不报** |

所以它是**符号检查器，不是主张检查器**。状态升格、否定断言、方向翻转这三类它结构上看不见。

把叙述拿来注入，每一处错误都是我们自己放进去的，**答案已知**，所以检出率是精确的、不需要任何生物学真值，也不需要调用模型。

### 3.2 错误分类（每条都要有检出/未检出两种结果）

按 D7 拆开：**这一轮只测现有检查器能负责的两类**，其余三类记为已知缺口。

| 类型 | 注入方式 | 负责检出的机制 | 本轮 |
|---|---|---|---|
| **C1 未获准实体** | 点名一个不在 `supported`/`single_source` 里的调控者，且该符号不在输入基因里 | `unsupported_claims()` | **测** |
| **C3 越界基因** | 引用一个不在输入基因、也不在任何被引集合里的符号 | `unsupported_claims()` | **测** |
| **C6 干净对照** | 原始未改动的叙述 | — | **测**（误报率必须 0） |
| **C2 状态升格** | 把 `single_source` 写成"被证实""驱动""机制" | **无** | 记为缺口 |
| **C4 反向断言** | 把 `untested` 说成"未发现"/"不存在" | **无**（若被报，是因为符号不在词表，属偶然） | 记为缺口 |
| **C5 方向翻转** | 方向与 `direction`/`perturbation_effect` 相反 | **无** | 记为缺口 |

C2/C4/C5 的检测器需要读懂"主张强度、否定、方向"，是语言层面的判断。
`interpret()` 里确有一个能看这些的 **LLM 审稿器**（`R/interpret.R:721` 那段 schema，
含 `OVERCLAIMING` 规则），但它要调模型，不满足"离线、零成本、可无限重复"的要求。
所以把它们并入 E1 会把 E1 从"离线测量"变成"要模型的重活"。**按 D7 留到另立方案。**

C6 是必需的：一个"什么都报"的检查器在检出率上是满分，在价值上是零。

### 3.3 接口

```r
# 内部，新增文件 R/evaluation_narrative.R
.mechanism_corrupt(narrative, kind, adj)   # -> 注入后的文本
.mechanism_detect(narrative, adj)          # -> 检出结果（复用 unsupported_claims）
.mechanism_injection_report(adj, narrative, kinds = ...)  # -> data.frame
```

输出列：`kind`、`injected`（注入了几处）、`detected`（检出几处）、`rate`。

`.mechanism_detect()` 直接包一层 `unsupported_claims()`，**不重新实现词表逻辑**——
E1 的目的是量它的边界，不是替换它。

### 3.4 叙述样本从哪来

三种，按可得性降级：

1. **录制的真实模型输出**（`adjudicate-interpret/results/` 下）——最真实，但需要先跑一次模型；
2. **模板合成的合规叙述**——由裁决表直接生成"每行一句"的叙述，天然满足 C6；
3. **手写的最小合规叙述**——一两个实体，够测就行。

**E1 不要求第 1 种**。第 2 种足以让 C1–C5 有对象可注入，且完全离线。

### 3.5 验收

1. C1、C3、C6 各有用例；检出率与误报率写入报告，C6 的误报率必须为 **0**。
2. C2/C4/C5 不测，但在报告里**写明为何不测**（D7），不要让空位被读成"测了且通过"。
3. **词表漏洞的用例（D8）**：同一句"ESR1 驱动了这个程序"，在
   (a) ESR1 不在输入基因里、(b) ESR1 在输入基因里 两种构造下都要被检出。
   修之前 (b) 放行，修之后 (b) 必须报。
4. 全部离线，`make check` 内运行，无模型、无网络。

### 3.6 E1 结果（2026-10-29 实测，MCF-7 / ESR1 KO）

`adjudicate-interpret/scripts/18_narrative_injection.R`。66 输入基因、871 条 verdict、
合规叙述 550 字符。C1 **全池测**（602 个未获准且形状像符号的调控者），不是抽样。

| 类型 | 用例 | 检出 | 检出率 |
|---|---|---|---|
| C1 未获准实体 | 602 | 588 | **97.7%** |
| C3 编造符号 | 602 | 602 | **100%** |
| C6 干净叙述（误报） | 1 | 0 | — |

**第一次测出来 C1 只有 96.8%（583/602），19 个漏检，原因有两类：**

1. **符号形状规则过宽（5 个，已修）**：`caps` 里有一条「单字母 + 数字一律视为列表标记」
   （`^[A-Z][0-9]+$`），本意是滤掉 `A4`、`Q4` 这类图注编号。但 `P53`、`P63`、`P68`、
   `P300`、`F10` 都符合这个形状，于是**一个叙述可以把 p53 说成机制而检查器看不见**。
   收紧为单字母 + **一位**数字后，这 5 个被检出，C1 升到 97.7%。
   图注编号（`A4`）仍然被抑制，没有变成噪音。
2. **族名前缀豁免（14 个，保留）**：`EGR`→`EGR1`、`STAT`→`STAT6`、`GATA`→`GATA3`、
   `PAX`→`PAX3-FKHR` 等。这是有意为之——允许用族名指代已获准的成员。代价是
   **一个恰恰叫这个前缀的未获准因子会漏检**。这是取舍，不是缺陷；但**这 14 个是已知的
   盲区**，不该被读成"检查器能捕获所有未获准实体"。

### 3.7 未测三类，且已实测确认检不出

C2/C4/C5 不在表里，用一个在词表里的实体探测，确认是结构缺口而非符号词表问题：

```
「ESR1 has been proven to drive this programme.」-> 报 0 个
「ESR1 is repressed here.」（与 direction 相反）  -> 报 0 个
```

两条都用了已获准实体，所以报 0 只能是"读不懂主张强度/方向"，不是"符号不认识"。

## 4. E2：分层扩规模 benchmark

### 4.1 现状

`adjudicate-interpret/scripts/12_channel_retest.R` 已有机制：GPSAdb 数据集 → 取该数据集自身的差异基因 → `evidence(upstream="tf")` → 看真值名次。当前 54 个，`tf` 找到 15/54，名次 = 1 的只有 1 个、≤10 的只有 1 个、≤20 的 3 个。

MRR 有两种口径，报告里必须说清用哪个：只算找到的 15 个是 0.083；把 39 个未找到按 0 计入全部 54 个是 **0.023**。**汇总用后者**，前者会把 39 次失败藏起来。

### 4.2 扩展

**样本量**：54 → 200–300。判据是 GPSAdb 中人类敲低数据集的可得数量，不设人为上限。

**分层**（每层单独报指标，不合并）：

| 层 | 定义 | 预期 |
|---|---|---|
| **S1** | 真值在 C3:TFT 里有集合 | 找到率应显著高于 S2 |
| **S2** | 真值不在 C3:TFT，但在并集库里有 | 用 `tf` 应接近 0（结构性），用 `tfunion` 应回到 S1 水平 |
| **S3** | 两层都没有 | 真值必然找不到，所以**不报"找到率"**；改报**错误自信率**——工具是否仍输出 `supported` 并给出一个确定答案 |

S1/S2/S3 的划分是**确定性的**（查集合即可），不需要人工标注。S2 是 `tfunion` 价值的直接量化。

S3 的判据初稿写成"不产生 `supported`"，这是错的：真值不在库里，本来就不可能为真值产生
`supported`，那句话是同义反复。S3 真正要问的是——**面对一个库里没有答案的问题，工具会
沉默还是会给一个自信的错误答案**。所以 S3 报"错误自信率"：`supported` 数 / 运行次数。

**分层内的两个配置**：`upstream="tf"` 与 `upstream="tfunion"`，同一批数据集，配对比较。

**⚠ 不允许加 `perturbagen` 配置。** 这条不是风格偏好：E2 的输入基因与真值**都来自
GPSAdb 同一个数据集**，而 `perturbagen` 通道用的证据也是 GPSAdb 数据集。真值数据集
若同时充当证据来源，评估就是自引用的——§R3 里 `biotrigger` 被判出局，正是栽在这个坑上。
`tf`（C3:TFT）与 `tfunion`（ChIP/motif/TFP）都不来自 GPSAdb 的敲低数据，所以安全。
后来者要加配置，必须先证明新来源与真值来源不重叠。

### 4.3 零分布

对每次运行，构造 **size 匹配的随机集合**：从该集合库中抽取与真值集合 `setSize` 相同数量的随机集合，得到真值名次的零分布，报告经验 p 值。

真值在库里没有集合时（S2 对 `tf`、S3 对两者）`setSize` 不存在，零分布无从匹配。
此时**不报经验 p**，报 `NA` 并注明"真值不在该库，名次不可比"——不要退化成用某个
默认 size 硬凑一个 p 值出来。S2 在 `tf` 下的预期本来就是"找不到"，给它一个 p 值反而
会让人以为那里有测量。

这一步把"名次 5"从无意义的数字变成"比同规模随机集合好的概率"。

### 4.4 中性负例层

新增一层对照，与真值层并列报告：

| 负例 | 构造 | 期望 |
|---|---|---|
| **N1 组织无关家族** | 嗅觉受体（`OR*`）作为基因列表，在胰腺/气道数据上跑 | 0 个 `supported` |
| **N2 随机基因集** | 同规模随机抽取 | 0 个 `supported`（**已有**，保留作弱对照） |
| **N3 标签置换** | 打乱集合库的 gsid↔基因对应 | `supported` 数显著下降 |

N1 是 D6 指定的强负例；N2 已有且为 0，保留说明两者差别（N1 的集合是真实的、能正常定级的）。

N3 与 N2 的效果高度重叠：打乱对应后，每个集合就是一组随机基因，与 N2 同类。
它的**独有价值**只剩一点——保留集合的 **size 分布与数量**，所以能排除"随机集之所以为 0
是因为它们比真实集合小"。如果实测 N2 与 N3 结果一致，N3 可以删掉，别为了凑三档留着。

### 4.5 输出

`adjudicate-interpret/results/` 下：

- `benchmark_tiered.tsv` —— 每条数据集一行：真值、层、配置、名次、找到与否、覆盖、经验 p
- `benchmark_summary.md` —— 按层的汇总表 + 中性负例结果

### 4.5b E2 结果（2026-10-29，264 个数据集）

`adjudicate-interpret/scripts/16_benchmark_discover.R` + `17_benchmark_tiered.R`。
全量跑 70.2 分钟。真值 = GPSAdb 数据集自己敲掉的因子。**没有 perturbagen 臂**（自引用）。

| 层 | 臂 | n | 找到 | 找到率 | top1 | top10 | MRR（全 layer） | 找中位名次 |
|---|---|---|---|---|---|---|---|---|
| S1 | `tf` | 31 | 11 | 0.355 | 0 | 2 | **0.0233** | **61** |
| S1 | `tfunion` | 31 | 15 | 0.484 | 0 | 0 | 0.0020 | 297 |
| S2 | `tf` | 33 | **0** | **0.000** | 0 | 0 | 0 | — |
| S2 | `tfunion` | 33 | **26** | **0.788** | 0 | 5 | **0.0633** | 212 |
| S3 | `tf` | 200 | 0 | 0.000 | 0 | 0 | 0 | — |
| S3 | `tfunion` | 200 | 0 | 0.000 | 0 | 0 | 0 | — |

**两个结论，一个证实、一个反直觉：**

1. **S2 证实了 `tfunion` 的价值**：`tf` 找到 **0/33**（结构上不可能，库里 0 个集合），
   `tfunion` 找到 **26/33 = 78.8%**。这是上一轮 4 个例子里"并集库值不值"那条判断的
   n=33 级证据，不再是轶事。
2. **S1 上 `tfunion` 反而更差**：找到率从 35% 升到 48%，但 **MRR 从 0.0233 掉到 0.0020**、
   中位名次从 61 掉到 297。多出来的 1755 个集合把正确答案找到了、也把它埋得更深。
   **召回与排序是两件事，加库换召回、不是换排序。** 这条在 4 个例子里完全看不见。

**指标缺陷（本轮未修）**：表里的 `truth_in_significant` 与 `found` 等价，它量的是
"真值出现在显著实体里"，**不是** `adjudicate()` 的 `supported` 数。S3 真正要问的
——面对库里没有答案的问题会不会仍给出 `supported`——**需要一个额外跑裁决的臂，本轮没测**。
不要把 S3 的 0 读成"已测且为 0"。

### 4.5c S3 与中性负例 N1 —— 两项都撞上同一个结构问题（2026-10-29）

`adjudicate-interpret/scripts/19_negative_controls.R`。

**S3 的错误自信率测不出来，原因是结构性的，不是没跑。**

`adjudicate()` 要求 `min_independent = 2` 个**独立来源**才给 `supported`。benchmark 里
只允许集合臂（`tf` / `tfunion`），而 tfunion 是 C3:TFT 的超集（交集 971，多出 365），
**两者不是独立来源**。实测 20 个 S3 数据集：

```
supported 0 个   single_source 13078 个   真值被判 single_source 0 个
```

`supported` 恒为 0 是必然结果。**那个 0 不能读作"校准良好"**，因为任何只用集合臂的设计
都会得到同样的 0。要真正测它，需要一个与真值来源不重叠的实测通道——而在 GPSAdb 当真值
的 benchmark 里，那正是 `perturbagen`，也就是被自引用防护禁掉的那个。

**N1 中性负例：通过，但证明力有限（同样因为上面的原因）。**

嗅觉受体（GO:0004888）1349 个基因，其中 **1281 个（95%）落在气道数据背景里**——
这一点很关键：不在背景里的基因会被判 `untested`，那样得到的 0 是"没测"而不是"测了没有"。

| 输入 | 显著集合行 | single_source | supported | absent | untested |
|---|---|---|---|---|---|
| 1281 个嗅觉受体 | **7**（1114 组里 0.6%） | 4 | 0 | 722 | 108 |
| 同规模随机基因（N2） | — | 1 | 0 | — | — |

工具没有为一份与该组织无关的真实基因集编造机制：1114 个集合里只有 7 行显著，
`supported` 为 0。但 **N1 相对 N2 的优势也被削弱了**：既然 `supported` 结构上到不了，
N1 与 N2 的差别只剩"4 个 vs 1 个 single_source 假设"，样本太小，不足以下强结论。

**N1 的真正价值仍然成立**：它是真实基因集，能正常富集、正常定级，唯一的区别是不该解释
这个实验——随机集做不到这一点。但要让它成为**有区分力的**负例，指标必须换成显著集合行数
（7 vs 随机集），而不是 `supported`。

### 4.6 验收

1. 每个层至少 20 个数据集；某层不足时显式标注"样本不足，不作结论"。
2. S2 在 `tf` 下的找到率应接近 0，在 `tfunion` 下应接近 S1；**若不成立，说明分层或实现有问题**，需先查清再报告。
3. 中性负例 N1 的 `supported` 数必须为 **0**。若不为 0，是一个需要单独解释的缺陷。
4. 报告中不得出现"总体准确率"这类单值。

## 5. E3：覆盖可见性

### 5.1 问题

airway 的 GR 是 A 级 `supported`，建立在 `Count=23 / 我的列表 896 = 2.6%` 上，而 26 个扰动数据集的覆盖中位是 17%。`print()` 只展示前 10 行，GR 不在其中，所以**看不出它靠什么撑起来**。

### 5.2 方案（最小侵入）

不改 `verdict`，不在表里加列，只做两件事：

1. **`print.evidenceBundle`**：在 `measured:` 那一行后面追加覆盖摘要——中位覆盖比例，以及覆盖低于阈值的数据集数。
2. **`print.adjudication`**：对 `supported` 的实体，若其 measured 来源的覆盖低于阈值，在摘要行标注。

**覆盖的定义要写死，因为这里有两个不同的比值容易混**：

- 本文用的覆盖 = `Count / 输入基因数` —— "这个数据集解释了我列表的多大比例"，airway 的 GR 是 23/896 = 2.6%；
- `diagnostics$counts` 里的 `coverage_tested` = "我的基因里有多少落进该来源的集合" —— 那是集合层的事，扰动通道没有 diagnostics 行。

两者不可互换。另外 `perturbagen` 表已按 regulator 去重（每组只留最好的那个数据集），
所以标注里的覆盖指的是**去重后留下的那个数据集**，不是该因子所有数据集的平均。

阈值：`options(clusterProfiler_coverage_note = 0.05)`，默认 5%（远低于实测中位 17%，只标异常）。

### 5.3 不做

- 不加 `coverage_floor` 到扰动通道——那是行为变更，会改动现有判定，不在本轮。
- 不在 verdict 表加列——冻结列集已定，追加需另立决策。

### 5.3b E3 已实现（2026-10-29）

落在 `R/evidence.R`（`.mechanism_measured_coverage()`、`.mechanism_thin_supported()`）
与两处 print。实测输出：

```
<adjudication>
  evidence:     896 genes, perturbagen
  verdicts:     supported 1  single_source 0  absent 0  untested 0
  supported:    GR (A)
  thin:         GR (2.6% of input) -- supported, but the measured evidence covers little of the input
```

bundle 侧在 `measured:` 行之后多一行 `coverage: median 2.6% of the input; 3 of 26 dataset(s) below 5%`
（健康时写作 `none below 5%`，不写 `0 of N`）。

两处细节值得记：

- **覆盖行放在 `queried` 属性判断之外**。计数行需要那个属性，覆盖行不该因为它缺失就一起消失——
  描述性信息的存在与否，不应取决于一条统计属性有没有被记上。
- **只有依赖 measured 来源的 `supported` 才标 `thin`**。仅靠集合来源支持的实体没有覆盖可言，
  给它写 `0%` 不是保守，是错的。

### 5.4 验收

1. 构造一个覆盖 2% 的 measured 行，`print()` 输出中出现提示；覆盖 40% 的输出中没有。
2. 阈值可通过 option 调整，设为 0 时一律不提示。
3. 任何 `verdict` 取值不变（用现有测试确认）。

## 8. 风险

- **风险**：E1 的注入叙述由我们自己合成，可能比真实模型输出"更规整"，从而高估检出率。缓解：报告里注明样本来源；有真实录制输出时优先用真实输出重跑一遍并对比。
- **风险**：E2 的 GPSAdb 数据集覆盖面偏颇（有的细胞系/方法占多数）。缓解：按细胞系与方法分层做敏感性分析，不合并成一个数。
- **风险**：E3 的阈值 5% 是拍出来的。缓解：先跑 E2 拿到覆盖分布，再据此定；在此之前只用它做"异常提示"，不用它做任何判定。
- **回退**：E1 与 E3 各自独立提交；E2 只产出结果文件，不改包。
