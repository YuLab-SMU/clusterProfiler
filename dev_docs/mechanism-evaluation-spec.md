# 机制提出评估框架：实现规范

状态：待实现。日期 2026-10-29。
构想与论证见 `dev_docs/mechanism-evaluation-proposal.md`。

---

## 1. 目标与范围

把当前"四个例子 + 一个 54 数据集 benchmark"的验证，扩成**可重复、分层、含非循环负对照**的评估框架，并修掉审查中发现的覆盖不可见问题。

三块工作，按性价比排序：

| # | 工作 | 回答什么 | 需要模型 | 需要网络 |
|---|---|---|---|---|
| **E1** | 叙述错误注入套件 | precision：它会不会把没证据的东西说成机制 | **否** | 否 |
| **E2** | 分层扩规模 benchmark | recall：找到率与名次，按真值可得性分层 | 否 | 是 |
| **E3** | 覆盖可见性 | 让"强"与"弱"看起来不一样 | 否 | 否 |

---

## 2. 决策

| # | 决策 | 理由 |
|---|---|---|
| **D1** | E1 注入的对象是**叙述文本**，不是 prompt | 注入 prompt 只能测"闸门挡没挡住"，而闸门逻辑已有单测。注入叙述测的是**安全检查本身灵不灵**，且完全离线、每一处错误都有确定答案 |
| **D2** | E1 的指标是**按错误类型的检出率 + 干净叙述上的误报率**，不合并成单分 | 与《单细胞…评估框架》§12-7 一致；合并会掩盖"某一类错误完全检不出" |
| **D3** | E2 **按真值可得性分层报告**，不报总体单值 | 「真值在 C3:TFT 里」是确定性分层，不需要人工标注；不分层会把两种完全不同的失败混成一个数 |
| **D4** | E2 增加**同 size 匹配随机集合**作为经验零分布 | 名次本身没有解释力；"比同规模随机集合好多少"才有 |
| **D5** | E3 **不改任何 verdict 判定**，只让覆盖可见 | 改判定会推翻已有结论，而那些结论本身没有错——它们只是缺一个"靠什么撑起来"的说明 |
| **D6** | 中性负例（组织无关真实基因集）进 E2 的负对照层 | 随机基因集是弱负例：显然无意义、工具不给结论是廉价的。真实集合才检验"会不会给出貌似合理的错误答案" |

## 3. E1：叙述错误注入

### 3.1 为什么注入叙述

`interpret()` 的输出受 `adjudication` 约束。这条约束有两道：

1. **闸门**：未获准的实体进不了 prompt（`evidence_admitted()` 与 `consensus_findings()` 的白名单）——已有单测覆盖；
2. **安全检查**：模型仍可能写出越界句子，由 `unsupported_claims()` 逐主张核验。

第 2 道**从未被单独测量过**。它存在，但没人知道它覆盖哪些错误、漏哪些。

把叙述拿来注入，每一处错误都是我们自己放进去的，**答案已知**，所以检出率是精确的、不需要任何生物学真值，也不需要调用模型。

### 3.2 错误分类（每条都要有检出/未检出两种结果）

| 类型 | 注入方式 | 期望 |
|---|---|---|
| **C1 未获准实体** | 叙述里点名一个不在 `supported`/`single_source` 里的调控者，并称其"调控"了通路 | 检出 |
| **C2 状态升格** | 把一个 `single_source` 实体写成"被证实""驱动""机制" | 检出 |
| **C3 越界基因** | 叙述里引用一个不在输入基因、也不在任何被引集合里的符号 | 检出 |
| **C4 反向断言** | 叙述把 `untested` 说成"未发现"/"不存在" | 检出 |
| **C5 方向翻转** | 叙述给某实体的方向与 `direction`/`perturbation_effect` 相反 | 检出 |
| **C6 干净对照** | 原始未改动的叙述 | **不报**（误报率） |

C6 是必需的：一个"什么都报"的检查器在检出率上是满分，在价值上是零。

### 3.3 接口

```r
# 内部，新增文件 R/evaluation_narrative.R
.mechanism_corrupt(narrative, kind, adj)   # -> 注入后的文本
.mechanism_detect(narrative, adj)          # -> 检出结果（复用 unsupported_claims）
.mechanism_injection_report(adj, narrative, kinds = ...)  # -> data.frame
```

输出列：`kind`、`injected`（注入了几处）、`detected`（检出几处）、`rate`。

### 3.4 叙述样本从哪来

三种，按可得性降级：

1. **录制的真实模型输出**（`adjudicate-interpret/results/` 下）——最真实，但需要先跑一次模型；
2. **模板合成的合规叙述**——由裁决表直接生成"每行一句"的叙述，天然满足 C6；
3. **手写的最小合规叙述**——一两个实体，够测就行。

**E1 不要求第 1 种**。第 2 种足以让 C1–C5 有对象可注入，且完全离线。

### 3.5 验收

1. 六类各有用例，C1–C5 的检出率写入报告，C6 的误报率必须为 **0**（干净叙述不许被报）。
2. 任一类型检出率低于 0.5 时，在报告里显式标出（**不视为失败**，视为"这道检查对该类错误无效"的结论）。
3. 全部离线，`make check` 内运行，无模型、无网络。

## 4. E2：分层扩规模 benchmark

### 4.1 现状

`adjudicate-interpret/scripts/12_channel_retest.R` 已有机制：GPSAdb 数据集 → 取该数据集自身的差异基因 → `evidence(upstream="tf")` → 看真值名次。当前 54 个，`tf` 找到 15/54，MRR 0.083。

### 4.2 扩展

**样本量**：54 → 200–300。判据是 GPSAdb 中人类敲低数据集的可得数量，不设人为上限。

**分层**（每层单独报指标，不合并）：

| 层 | 定义 | 预期 |
|---|---|---|
| **S1** | 真值在 C3:TFT 里有集合 | 找到率应显著高于 S2 |
| **S2** | 真值不在 C3:TFT，但在并集库里有 | 用 `tf` 应接近 0（结构性），用 `tfunion` 应回到 S1 水平 |
| **S3** | 两层都没有 | 找到率应接近 0，且 **不产生 `supported`** |

S1/S2/S3 的划分是**确定性的**（查集合即可），不需要人工标注。S2 是 `tfunion` 价值的直接量化。

**分层内的两个配置**：`upstream="tf"` 与 `upstream="tfunion"`，同一批数据集，配对比较。

### 4.3 零分布

对每次运行，构造 **size 匹配的随机集合**：从该集合库中抽取与真值集合 `setSize` 相同数量的随机集合，得到真值名次的零分布，报告经验 p 值。

这一步把"名次 5"从无意义的数字变成"比同规模随机集合好的概率"。

### 4.4 中性负例层

新增一层对照，与真值层并列报告：

| 负例 | 构造 | 期望 |
|---|---|---|
| **N1 组织无关家族** | 嗅觉受体（`OR*`）作为基因列表，在胰腺/气道数据上跑 | 0 个 `supported` |
| **N2 随机基因集** | 同规模随机抽取 | 0 个 `supported`（**已有**，保留作弱对照） |
| **N3 标签置换** | 打乱集合库的 gsid↔基因对应 | `supported` 数显著下降 |

N1 是 D6 指定的强负例；N2 已有且为 0，保留说明两者差别（N1 的集合是真实的、能正常定级的）。

### 4.5 输出

`adjudicate-interpret/results/` 下：

- `benchmark_tiered.tsv` —— 每条数据集一行：真值、层、配置、名次、找到与否、覆盖、经验 p
- `benchmark_summary.md` —— 按层的汇总表 + 中性负例结果

### 4.6 验收

1. 每个层至少 20 个数据集；某层不足时显式标注"样本不足，不作结论"。
2. S2 在 `tf` 下的找到率应接近 0，在 `tfunion` 下应接近 S1；**若不成立，说明分层或实现有问题**，需先查清再报告。
3. 中性负例 N1 的 `supported` 数必须为 **0**。若不为 0，是一个需要单独解释的缺陷。
4. 报告中不得出现"总体准确率"这类单值。

## 5. E3：覆盖可见性

### 5.1 问题

airway 的 GR 是 A 级 `supported`，建立在 `Count=23 / 我的列表 896 = 2.6%` 上，而 26 个扰动数据集的覆盖中位是 17%。`print()` 只展示前 10 行，GR 不在其中，所以**看不出它靠什么撑起来**。

### 5.2 方案（最小侵入）

不改 `verdict`，不在表里加列，只做两件事：

1. **`print.evidenceBundle`**：在 `measured:` 那一行后面追加覆盖摘要——中位覆盖比例，以及覆盖低于阈值的数据集数。
2. **`print.adjudication`**：对 `supported` 且唯一 measured 来源覆盖低于阈值的实体，在摘要行标注。

阈值：`options(clusterProfiler_coverage_note = 0.05)`，默认 5%（远低于实测中位 17%，只标异常）。

### 5.3 不做

- 不加 `coverage_floor` 到扰动通道——那是行为变更，会改动现有判定，不在本轮。
- 不在 verdict 表加列——冻结列集已定，追加需另立决策。

### 5.4 验收

1. 构造一个覆盖 2% 的 measured 行，`print()` 输出中出现提示；覆盖 40% 的输出中没有。
2. 阈值可通过 option 调整，设为 0 时一律不提示。
3. 任何 `verdict` 取值不变（用现有测试确认）。

## 8. 风险

- **风险**：E1 的注入叙述由我们自己合成，可能比真实模型输出"更规整"，从而高估检出率。缓解：报告里注明样本来源；有真实录制输出时优先用真实输出重跑一遍并对比。
- **风险**：E2 的 GPSAdb 数据集覆盖面偏颇（有的细胞系/方法占多数）。缓解：按细胞系与方法分层做敏感性分析，不合并成一个数。
- **风险**：E3 的阈值 5% 是拍出来的。缓解：先跑 E2 拿到覆盖分布，再据此定；在此之前只用它做"异常提示"，不用它做任何判定。
- **回退**：E1 与 E3 各自独立提交；E2 只产出结果文件，不改包。
